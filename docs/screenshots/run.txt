calls `/-/load` at all — there is nothing to load in attach mode.

Known caveat — `run -p` one-shot output is unbounded
----------------------------------------------------

The `-p` one-shot path was exercised: it exited 0, but generated for
**285 s / 2206 lines** on a single short prompt (full transcript on record,
deliberately not reproduced here). Two facts are on file: the committed
completions body omits `max_tokens` (the pinned backend aborts a
completion without it), and the only fix so far is an uncommitted local
change that sends `"max_tokens": 0` — which means "generate to EOS, no
cap". Until that lands properly, do not treat an unbounded `-p` run as
normal behaviour: prefer a piped input such as the `/bye` capture above,
or budget time and cap tokens yourself.

Supervised (non-attach) `serve` and its `/-/load` SSE success stream were
NOT exercised: they need the provisioned Python runtime (`stone-llama
setup`, ~5.6 GB, never authorized on this machine) plus a second model
load contending for the same 4096 MiB card. Known untested path, not a
claim of support.
